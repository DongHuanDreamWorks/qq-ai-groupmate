# 安全、隐私与合规

## 1. 这是自动化 QQ 客户端

NapCat 在容器里运行**官方 QQ 客户端**并注入协议。这种行为**可能违反腾讯的服务条款**，
账号存在被限制登录、强制下线、甚至封禁的风险。

- **不要用主号。** 用一个专门的小号。
- 不要用这个号处理任何支付、实名、重要社交关系。
- 项目不提供、也不建议任何绕过风控的手段。

## 2. 仓库里没有什么

这个仓库**不包含**：

- 任何 QQ 号、密码、登录态、二维码、聊天记录
- 任何 API Key、Token、License
- `data/` 下的数据库、日志、图片
- 服务器 IP、域名、SSH 凭据

`.gitignore` 已忽略 `.env`、`data/`、`run/`、`*.log`、`initial_password.txt`。

如果你 fork 后要提交，提交前自查：

```bash
git grep -nE 'sk-[A-Za-z0-9]{16,}|[0-9]{10,}|BEGIN (RSA|OPENSSH)'
```

## 3. 密钥

| 密钥 | 存放 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | `.env` | 只进 Console 环境变量 |
| `BRAIN_TOKEN` | `.env` | 内部鉴权；泄露等于能伪造消息 |
| `NAPCAT_WEBUI_TOKEN` | `.env` | NapCat 面板，别暴露 6099 |
| 控制台密码 | SQLite（scrypt 哈希） | 首次随机生成或 `CONSOLE_PASSWORD` |
| `system.secret` | SQLite | Cookie 签名密钥，首次随机 |

轮换建议：`BRAIN_TOKEN` 泄露后改 `.env` 并重启 console + astrbot；
控制台密码在页面右上角改。

## 4. 公网暴露

- 默认只监听 `8088`，且**没有内置 TLS**。公网使用请加反向代理 + HTTPS。
- `6099` / `6185` 只绑 `127.0.0.1`，不要改成 `0.0.0.0`。
- 登录有 6 次 / 10 分钟限流，但弱密码仍会被撞，务必用长密码。
- `/api/gen/{name}` 不鉴权（NapCat 取图用），文件名随机；不要在这里放敏感图片。

## 5. 群友隐私

这是最容易忽略、也最重要的一条。

- 机器人会**保存群聊消息**到本地 SQLite，用于上下文与记忆。
- 「人物动态」会把 A 的发言摘要，在 B 提到 A 时带进上下文。
  **只给摘要，不给私聊原文**——这是有意的设计，但仍然是一种信息流动。
- 建议：在群公告里说明“本群有一个 AI 群友，会记录聊天用于上下文”，
  或者至少让群主/管理员知情。
- 被问“你是不是 AI”时人设要求如实承认；但**它不会主动声明**。
  如果你在意这一点，可以在人设里加一句“进群先自报 AI”。

## 6. 数据保留与删除

- 删除某个人的记忆：「长期记忆」页 → 删除。
- 清空某个群的上下文：「上下文」页 → 清空。
- 彻底删除：停容器，删 `data/console/brain.db`。
- 备份文件里同样包含聊天记录，注意存放位置。

## 7. 模型侧

- 消息会发给 DeepSeek API（或你配置的兼容网关），按对方的隐私政策处理。
- 图片以 base64 发送；GIF 只取第一帧。
- 新闻/天气来自公开 RSS 与 Open-Meteo，不含个人信息。

## 8. 报告问题

如果是安全漏洞（鉴权绕过、注入、密钥泄露路径），请不要开公开 issue，
先通过仓库主页留的方式私下联系维护者。
